Worum es geht

Anfragen an eine Rechtsabteilung kommen oft per E-Mail, Telefon oder Zuruf. Dadurch fehlen Informationen, Fristen gehen unter und niemand sieht, wie ausgelastet die Teams sind. Dieser Prototyp zeigt einen einheitlichen Eingang: ein Formular, eine zentrale Liste, feste Zuständigkeiten, Fristen und eine Auswertung. Er ist als klickbare Webseite gebaut, damit man den Ablauf ausprobieren kann. Die Seite unten zeigt, wie ich ihn mit der Microsoft Power Platform umsetzen würde.

Datenschutz und Sicherheit

  • Datensparsamkeit (Art. 5 DSGVO): Das Formular erkennt E-Mail-Adressen, Telefonnummern, IBAN und Geburtsdaten und schlägt Platzhalter vor.
  • Zugriff nach Rollen: Mitarbeitende sehen nur eigene Anfragen (Elementberechtigungen), die Rechtsabteilung sieht alle.
  • Nachvollziehbarkeit: Jede Statusänderung wird protokolliert (Versionsverlauf und Verlaufsfeld).
  • Löschkonzept: Erledigte Anfragen werden nach einer festgelegten Frist per Aufbewahrungsrichtlinie gelöscht.
  • KI mit Mensch: Die KI schlägt nur vor, die Entscheidung trifft eine Person. Die Konfidenz wird gespeichert.

Power Fx: Anfrage speichern

Patch(
  Rechtsanfragen,
  Defaults(Rechtsanfragen),
  {
    Title: txtBetreff.Text,
    Beschreibung: txtBeschreibung.Text,
    Kategorie: { Value: drpKategorie.Selected.Value },
    KI_Konfidenz: varKonfidenz,
    Status: { Value: "Eingegangen" },
    'Priorität': { Value: drpPrio.Selected.Value },
    Enthält_PbD: varPbDErkannt
  }
);
Notify("Anfrage eingereicht", NotificationType.Success);
ResetForm(frmAnfrage)

Power Automate: Routing-Flow

Trigger: Wenn ein Element erstellt wird (Rechtsanfragen)
1  Zeile aus Routing-Tabelle holen
   Filter: Kategorie eq triggerBody()?['Kategorie/Value']
2  Frist = addDays(utcNow(), Tage je Priorität)
   (Werktage über Hilfsliste Feiertage)
3  Element aktualisieren: Zuständig, Frist
4  Nachricht im Teams-Kanal des Teams posten
5  Bestätigung an die anfragende Person
Täglich 08:00: Elemente mit Frist < heute
   und Status ne 'Erledigt' → Erinnerung

Was in diesem Prototyp vereinfacht ist

  • Die Daten liegen nur im Browser der Person, die die Seite öffnet. Es gibt keinen Server und keine echten Personen.
  • Der KI-Vorschlag ist regelbasiert (gewichtete Schlüsselbegriffe), damit er transparent bleibt. In Microsoft 365 würde ein AI-Builder-Modell zur Kategorisierung mit echten, anonymisierten Anfragen trainiert.
  • Fristen werden in Werktagen ohne Feiertage gerechnet.
